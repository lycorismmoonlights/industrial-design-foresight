# 共研启动与提交模板

适用：设计牵头，计算机、人工智能、经管共同参与的首轮试点。所有空项由团队确认，不表示已完成。

## 1. 共研任务书

- 研究问题（限一个）：
- 候选产品 / 场景 / 适用地区：
- 为什么值得研究：
- 当前假设：
- 能推翻假设的现象：
- 本轮不研究的内容：
- 项目负责人 / 各方向复核人：
- 成员、每周投入与沟通方式：
- 证据和实验验收标准：
- 第 2 周 / 第 6 周检查日期：
- 模型调用、材料、访谈资源与费用上限（有需求再确认）：
- 贡献、署名、数据处理与公开范围约定：

## 2. 证据提交卡

| 字段 | 填写内容 |
|---|---|
| 证据编号 / 提交者 / 提交时间 | |
| 原始标题、机构、链接 | |
| 发布日期 / 查阅日期 | |
| 适用地区、行业、产品范围 | |
| 原始出处与转述关系 | |
| 来源类别 / 来源可信度先验 1–5 | |
| 支持 / 反对 / 背景 | |
| 与研究问题的相关度 1–5 | |
| 原文依据位置（节、段落或表号） | |
| 事实摘要（与个人解释分开） | |
| 提交者解释与建议关联的假设 | |
| 来源没有证明什么 | |
| 商业立场、采样局限、其他偏差 | |
| 独立性：是否与已有材料同源 | |
| AI 是否参与 / 人工修改记录 | |
| 专业复核意见 / 项目负责人处理结果 | |

来源先验不是结论置信度。官方来源也不能越过适用范围；同一报告的新闻、采访和转载不能当作三个独立来源。

## 3. 人工智能方向：最小评估记录

研究问题：AI 辅助整理是否在不增加无依据结论、遗漏反证的情况下，减少人工整理工作？该问题尚待验证。

建议先取 10 条有原文的公开资料作为探索样本，由两人独立标注后讨论分歧。冻结一部分资料作为留出检查集，提示词调整只使用其余资料。记录划分，不把同一材料或其转载放入两边。

| 项目 | 记录 |
|---|---|
| 样本编号、原文版本与采样规则 | |
| 人工基准摘要 / 立场 / 适用边界 | |
| 标注者、分歧与裁定理由 | |
| 调整集 / 留出检查集 | |
| 模型名称、调用日期、提示词版本 | |
| AI 原始输出与失败记录 | |
| 有原文支持的关键陈述数 / 总关键陈述数 | |
| 无依据陈述、错误归因、范围夸大 | |
| 原文含反证的条目数 / 被遗漏的条目数 | |
| 人工整理用时 / 辅助整理用时（含核验修改） | |
| 修改内容、最终可用性及复核意见 | |

小样本结果用“几条 / 共几条”和具体错误案例汇报，不外推通用模型能力。比较用时前约定相近难度的任务、分配方式和核验范围，记录顺序与熟悉效应。不能把处理耗时直接称为质量提升。

## 4. 计算机方向：数据质量交付

- 来源与采集方式；参数只保留非密钥字段。
- 字段字典：名称、类型、空值含义、单位、时间和地区。
- 获取条目数、重复数、无日期数、无原文数、失败数及计算口径。
- 同源转载和重复条目的判定规则。
- 一条失败案例及可复现步骤。
- 运行环境、脚本或代码版本、输入输出说明。
- 人工复核范围与尚未处理的问题。

## 5. 经管方向：需求与成本假设

- 目标用户是谁、什么场景出现需求：
- 当前如何解决、替代方案是什么：
- 哪种观察或回答会推翻需求判断：
- 服务、备件、价格或采用条件有哪些限制：
- 成本假设及来源（材料、装配、售后等；缺项标为待核验）：
- 访谈采样与知情同意方式（开展前确认）：
- 实际样本与偏差，不将意向回答视为支付行为：
- 对机会卡的支持、反对或暂缓意见：

## 6. 设计机会卡

- 机会名称 / 目标用户 / 使用场景：
- 对应问题与具体价值：
- 支持证据编号 / 反方证据编号：
- 未证实的关键假设：
- 最小验证任务 / 方法 / 预先约定的判定条件：
- 技术与安全约束及所需专业复核：
- 验证结果与限制：
- 继续 / 收缩 / 停止及理由：
- 负责人、下一次复核与各成员贡献：
